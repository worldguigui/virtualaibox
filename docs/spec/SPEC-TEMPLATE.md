# SPEC-TEMPLATE：spec 文件的通用模板

- 状态：Draft / Current / Deprecated
- 创建日期：2026-11-19
- 更新日期：2026-11-19

## 功能目标

- 说明这个 Spec 要解决什么问题。
- 说明设计这个功能的目的。
- 简要描述预期达到的效果。

## 功能范围

### 包含范围

1. 描述本 Spec 负责的功能。
2. 描述需要实现的行为。
3. 后续可以继续添加。

## 输入与输出

### 输入

| 名称 | 类型 | 说明 |
|---|---|---|
| 参数一 | 类型 | 参数说明 |
| 参数二 | 类型 | 参数说明 |

- 也可以使用文字描述输入。
- 如果存在复杂数据结构，可以单独定义数据模型。

### 输出

| 名称 | 类型 | 说明 |
|---|---|---|
| 结果一 | 类型 | 结果说明 |
| 结果二 | 类型 | 结果说明 |

- 说明正常情况下产生什么结果。
- 如果存在多种结果，需要分别说明。

## 核心行为

- 以分点形式描述功能的核心执行流程。
- 说明各个阶段需要完成的工作。
- 说明不同条件下系统应该采取什么行为。
- 如果存在状态变化，可以使用表格或状态图描述。
- 如果存在复杂业务规则，可以进一步拆分小节。

## 约束与不变量

- 记录功能必须遵守的约束。
- 记录任何情况下都必须成立的不变量。
- 记录输入、输出、状态或执行过程中的限制。
- 如果某项约束由其他 Spec 定义，可以引用对应文档。

## 异常处理

- 记录可能出现的异常情况。
- 说明不同异常发生时，系统应该如何处理。
- 说明异常是否影响当前操作、其他操作或整个执行流程。
- 如果存在重试、降级、回滚等机制，需要明确其行为。

## 验收标准

1. 验收条件一：描述必须满足的行为。
2. 验收条件二：描述必须满足的约束。
3. 验收条件三：描述异常情况下的预期结果。

- 验收标准应当能够被验证。
- 可以补充对应的测试方式或测试用例。

## 待解决问题（可选）

- 记录尚未确定的设计问题。
- 记录目前无法确认的行为或约束。
- 问题得到解决后，应将结论更新到对应章节，并删除已解决的问题。
